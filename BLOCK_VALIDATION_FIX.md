# Block Validation Error Fix

## Problem Identified

The console showed a **block validation error**:

```
Block validation: Block validation failed for `newopm/osm-map`

Content generated by `save` function:
<div id="newopm-map-zra8844ry" ...>

Content retrieved from post body:
<div id="newopm-map-uta2db8xi" ...>
```

**Root Cause:** The `save.js` function was generating a new random map ID on every render:
```javascript
const mapId = `newopm-map-${Math.random().toString(36).substring(2, 11)}`;
```

This caused WordPress to detect a mismatch between the saved content and the content generated by the `save()` function, triggering a validation error that could prevent the block from rendering properly.

---

## Solution Applied

### 1. Added `mapId` Attribute to `block.json`

```json
"mapId": {
    "type": "string"
}
```

This stores the map ID as a block attribute so it persists across saves.

### 2. Updated `save.js` to Use Stored ID

```javascript
const { latitude, longitude, zoom, markerLat, markerLon, markerLabel, height, width, mapId } = attributes;

// Use the mapId from attributes (generated once when block is created)
// Fallback to a generated ID for backwards compatibility with old blocks
const finalMapId = mapId || `newopm-map-${Math.random().toString(36).substring(2, 11)}`;
```

### 3. Updated `edit.js` to Generate ID Once

```javascript
// Generate and store a unique map ID when block is first created
// This ensures the ID stays consistent across saves and prevents block validation errors
useEffect(() => {
    if (!mapId) {
        setAttributes({
            mapId: `newopm-map-${Math.random().toString(36).substring(2, 11)}`,
        });
    }
}, []); // Empty dependency array = run once on mount
```

## What This Fixes

✅ **Block Validation Errors** - No more "Block validation failed" messages in console  
✅ **Consistent Map IDs** - Map IDs stay the same across saves  
✅ **Better Editor Experience** - Blocks load without validation warnings  
✅ **Backwards Compatible** - Old blocks without mapId will still work (with fallback)

---

## What This Doesn't Fix

This fix addresses the **block validation error**, but if you're still seeing **missing/scrambled tiles**, that's a separate issue related to:
- CSS not loading properly
- JavaScript errors
- Network issues loading tiles
- Browser cache

**For missing tiles, follow the debugging guide in `DEBUGGING_TILES_ISSUE.md`**
